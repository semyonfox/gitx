GitX 0.3.0

GitX quick guide

Find a tool, see where it came from, inspect it, then run an exact version. GitX is an opinionated wrapper around the tools already on your machine. It does not replace npm, Bun, pnpm, Git, or your platform package manager.

Start here

gitx doctor
gitx search ripgrep --device
gitx search formatter --source npm,github --details 1
gitx inspect npm:prettier@3.6.2
gitx exec prettier@3.6.2 --preview
gitx exec prettier@3.6.2 --yes -- --check README.md

search, inspect, and --preview never run a tool. run and exec ask before they run unless you pass --yes.

Use native tools when you know exactly what you want and raw speed matters. Use GitX when you want search across sources, a precise origin and version, compatibility notes, an update diff, or a preflight check.

The command tree

gitx [--color auto|always|never] [-v...] [--progress auto|always|never]
├── inspect SOURCE [--format text|json]
├── run SOURCE [--yes] [--preview] [-- ARGS...]
├── exec [TARGET] [-p PACKAGE]... [--bin BIN]
│   [--backend auto|bun|npm|pnpm] [--yes]
│   [--allow-scripts] [--allow-dangerous-scripts] [--preview] [-- ARGS...]
├── search QUERY [--recommend] [-n 1..20]
│   [--source SOURCE[,SOURCE]...] [--project DIR]
│   [--select SELECTION | --interactive | --details RESULT]
│   [--offline] [--device] [--catalog ID[,ID]...] [--format text|json]
├── install SOURCE [--as NAME]
├── update TOOL [--check]
├── list
├── remove TOOL
├── cache
│   ├── list
│   ├── clear
│   ├── remove KEY
│   └── import PACKAGE [--from auto|all|npm|pnpm|bun]
├── doctor
└── completion bash|elvish|fish|powershell|zsh

Every command accepts --help. The root command accepts --version. GitX colours human-readable output on a real terminal. Use --color always to force ANSI colour in a pager, or --color never for plain logs and scripts. NO_COLOR also disables automatic colour.

Global optionWhat it does
-v, --verboseWrite resolution, policy, and backend hand-off steps to standard error. Repeat as -vv for source-level search detail.
--progress autoDraw GitX-owned transfer progress and Git activity on an interactive standard-error terminal.
--progress alwaysForce the animated renderer when a terminal-aware wrapper hides TTY detection.
--progress neverDisable progress for logs and strict stderr parsers.

Verbose lines and progress stay on standard error, so JSON stays machine-readable on standard output. GitX draws an exact byte bar only for a transfer it owns, currently cache imports and the internal tarball downloader. Git fetches use the animated C--- marker because GitX cannot know their byte total. npm, Bun, and pnpm retain their own download UI after GitX hands work to them.

:: Importing cached package tarball complete: 22 KiB / 22 KiB

Search without running anything

gitx search eslint --device
gitx search eslint --source npm,github --details 1
gitx search eslint --offline --source installed,cache
gitx search eslint --source cache --select 1
gitx search eslint --catalog company-tools --format json
OptionWhat it does
--recommendMark the strongest displayed result as a suggestion. It never executes a tool.
--deviceStrictly local search. It reads GitX state, project bins, local caches, and usable platform catalogs. It never calls a registry or Git host.
--sourcePick one or more sources. Repeat it or separate values with commas.
--project DIRChoose the directory whose node_modules/.bin GitX searches. The default is the current directory.
--offlineSkip remote sources. An explicitly requested remote source fails rather than changing your request.
--details 1Show the full card for result 1, including origin, version, description, compatibility, and next action.
--select 1-3Print next commands for results. It does not execute them.
--interactivePrompt for result numbers in a terminal. It also only prints commands.
--limit 1..20Set the result limit. The default is 10.
--catalog IDRun a named user catalog from the GitX catalog configuration. Repeat it or separate values with commas.
--format jsonReturn machine-readable schema-version-2 output.

Sources are all, device, npm, bun, github, gitlab, codeberg, aur, installed, cache, project, system, apt, pacman, flatpak, snap, cargo, python, and npm-global. The platform-specific ones appear only when they are available on the machine.

GitX uses at most four local providers and four remote providers at once. Results still appear in a stable source order. With -v, GitX names every remote source as it begins. With -vv, it also reports source-level completion counts.

Inspect and run

gitx inspect ./tool
gitx inspect github:owner/repo@v1.2.0
gitx inspect npm:prettier@3.6.2 --format json

gitx run ./tool -- --fix
gitx run github:owner/repo@v1.2.0 --preview
gitx run github:owner/repo@v1.2.0 --yes -- --check

gitx exec prettier@3.6.2 -- --check README.md
gitx exec --package @angular/cli@20.0.0 --bin ng -- new app

run is for a Git repository that contains a schema-1 gitx.toml. GitX resolves a remote ref to a commit before running it. exec is for npm package binaries. It resolves the exact package version and checks registry metadata before it delegates to npm, Bun, or pnpm.

All inspect options
SOURCERequired local directory, GitX-style Git source, generic Git URL, or npm package spec.
--format text|jsonHuman-readable output or machine-readable inspection data. Text is the default.
All run options
-y, --yesSkip confirmation.
-n, --previewShow the preflight and stop before execution.
-- ARGS...Forward the remaining arguments to the manifest entrypoint.
All exec options
TARGETA package spec, or a binary name when --package is present.
-p, --package PACKAGERepeatable package to make available to the command.
--bin BINExplicit binary. It requires one or more --package values.
--backend auto|bun|npm|pnpmSelect the package manager after preflight. auto is the default.
-y, --yesSkip confirmation.
--allow-scriptsAllow install lifecycle scripts in the delegated backend.
--allow-dangerous-scriptsAcknowledge a deny-level lifecycle finding. It requires --allow-scripts.
-n, --previewShow the resolution and preflight without execution.
-- ARGS...Forward the rest to the package binary.

GitX checks integrity metadata, install lifecycle scripts, suspicious script patterns, large dependency counts, and native-looking package names. It is not a sandbox and it does not yet scan extracted files or the full dependency tree.

Install, update, and remove

gitx install prettier@3.6.2
gitx install github:owner/repo@v1.0.0 --as repo-tool
gitx list
gitx update prettier --check
gitx update prettier
gitx remove prettier

install creates a GitX-managed shim pinned to an npm version or Git commit. update --check resolves again and shows the exact diff without writing. An actual update compares the pin, integrity, description, homepage, license, entry point, binary names, platform rules, runtime requirements, and manifest metadata.

Records live in ~/.gitx/installed and shims in ~/.gitx/bin, unless GITX_HOME changes that location.

All persistent-install commands
gitx install SOURCECreate a managed shim for the source.
install --as NAMEName the shim instead of using the inferred binary or tool name.
gitx update TOOLResolve the original source, show the diff, and write an update if needed.
update --checkShow the same diff without changing the record or shim.
gitx listList managed shims.
gitx remove TOOLRemove one managed shim and its record.

Cache and completions

gitx cache list
gitx cache import cowsay@1.6.0 --from npm
gitx cache remove cowsay
gitx cache clear

gitx completion bash > ~/.local/share/bash-completion/completions/gitx
gitx completion zsh > ~/.zfunc/_gitx

cache clear clears GitX's local cache only. It does not wipe normal npm, Bun, or pnpm caches. Set GITX_CACHE_DIR to choose the GitX cache location. Without it, GitX uses $XDG_CACHE_HOME/gitx or ~/.cache/gitx.

Pnpm delegated runs now keep both its dlx cache and store below the GitX cache. Bun can still satisfy a package from its shared global cache, so call a Bun cache test warm unless you use a clean user or container.

All cache, doctor, and completion commands
gitx cache listList GitX-owned cached artifacts.
gitx cache clearClear the GitX local cache only.
gitx cache remove KEYRemove one GitX cache record, package, commit, or tool key.
gitx cache import PACKAGEImport a verified package artifact from another local cache.
cache import --from auto|all|npm|pnpm|bunChoose which existing cache to read. auto tries npm first. all checks npm, Bun, and pnpm.
gitx doctorReport the supported runtimes available on PATH.
gitx completion SHELLWrite a completion script to standard output for bash, elvish, fish, powershell, or zsh.

What the timing run found

These are three-run means on Ubuntu 24.04.4. They are a snapshot, not a universal benchmark.

TaskGitXNative or rawRead
APT catalog search0.377 s0.343 sGitX adds 0.034 s.
npm registry search0.297 s0.277 sVery close after the cold request.
GitHub repository search0.213 s0.077 sCard parsing and normalization cost time.
Codeberg repository search3.757 s3.690 sThe remote server owns almost all of the wait.
npm package run, cold1.533 s1.370 sGitX adds 0.163 s.
pnpm package run, cold1.497 s1.330 sGitX adds 0.167 s.

The honest answer is simple. GitX loses a little time to direct provider calls. That is where it cannot beat the originals. Its value is the common interface and the information around the command, not raw single-command speed.

Current limits

GitX is good for internal development and testing. It is not a security sandbox. Manifest permissions only inform the preflight. It still needs direct execution from verified GitX-owned package artifacts, full package file scanning, configured private-registry execution, semver range resolution, Windows-native shims, and a clean-environment Bun cold-cache test.

Run gitx <command> --help for the built-in reference. This page covers GitX 0.3.0.
